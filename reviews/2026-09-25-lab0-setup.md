## 关键决定：测试程序先自证，再交付

没有直接把测试交给学员。先写了两份一次性参考实现（Python ISS + 一个 SV 核，都只在 `/tmp`，**没进仓库**）把 5 个测试全跑 PASS，结果查出 **3 个测试程序自己就是错的**：

| 问题 | 现象 |
|---|---|
| `la s9, auipc_here` | 裸机下 `la` 展开成 `auipc` + **`lw` from GOT**，取到 0。必须用 `lla` |
| 斐波那契循环次数差一 | 循环 20 次得到 fib(21)=10946，期望值写的是 fib(20)=6765 |
| 用 `t6` 当数据寄存器 | `CHECK` 宏正好要写 `t6` 存失败编号，断言恒失败 |
| 负偏移测试写到 `0x40c` | 那是上一条 CHECK 刚验证过的字，期望值被自己踩了 |

**为什么值得花这个时间**：如果不先验证，学员会拿着错误的预期值去调自己的 RTL，卡住时完全无法判断是 RTL 错还是测试错——这是最浪费时间的一种卡法。

## 搭参考实现时踩到的两个 RTL 坑（已写进 README 提醒学员）

1. **`logic [31:0] x = expr;` 这种声明初始化器，不能当组合逻辑用。** 参考实现里写了 `logic [4:0] rs1 = (opcode == OP_LUI) ? 0 : instr[19:15];`，Verilator 把它当一次性初始化冻住了，`rs1` 恒为 0。波形上完全看不出来，只有 `dmem_addr` 莫名其妙是 0。**要写 `assign`。**
2. **load/store 的地址计算不能复用指令的 ALU 译码。** `sw` 的 funct3 = `010`，按 funct3 无脑译码会当成 `slt`，地址就变成比较结果。
